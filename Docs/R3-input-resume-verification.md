## 변경

- 키(기본·extended), 유니코드, 마우스 버튼, 0이 아닌 휠 입력은 C 브리지에서 로컬 GDI 억제 상태를 확인한다. 기존 `RDPSession` 세션 락이 잡힌 같은 호출 스레드에서 Allow → 협상된 경우 전체 RefreshRect → 입력 순서로 호출한다. 별도 락·상태 플래그를 추가하지 않았다.
- C 콜백 → RDPSessionDelegate → RDPConnectionView의 비동기 메인 큐 경로로 정책을 false로 맞추고, 여전히 숨겨졌을 때만 기존 1초 디바운스를 처음부터 시작한다. 선로와 정책 상태가 일시적으로 다를 수 있다는 결정에 따른다. 중복 억제 요청은 GDI 상태로 생략한다.
- 단순 이동은 해제하지 않는다. Windows Server 2019 기존 실측은 키 입력 소실만 확인했으며 이동에 대한 근거는 없다. 명시적 정책 결정대로 버튼·휠만 포함했다. `RDPSharedInputSession`은 이미 같은 RDPSession 입력 API를 쓰므로 변경하지 않았다.
- 억제 지원 caps가 사라져도 해제는 GDI를 복구한다. 입력 전 해제/RefreshRect가 실패하면 해당 입력을 전송하지 않고 오류를 반환한다. FreeRDP가 실패 시에도 로컬 GDI를 먼저 바꾸는 경우에는 변경된 상태를 콜백으로 알린다.
- 첫 network auto-detect 로그를 서버 초기값(기본값일 수 있으며 링크 실측 추정치로 단정 불가)으로 표시한다. 종료 요약은 `bandwidthPresent`를 표시해 해당 결과에 대역폭 필드가 없는 경우의 0을 0 처리량으로 해석하지 않도록 한다.
